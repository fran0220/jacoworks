# Agent City 团队协作规则

## 内容规范

1. **产出目录** — 所有内容产出必须放在 `content/{YYYY-MM-DD}/{role}/` 下，按日期和角色组织
2. **文件格式** — 统一使用 Markdown 格式，文件名使用有意义的中文或英文命名
3. **元信息** — 每篇内容顶部注明作者角色、创建时间、关联赛事 ID
4. **数据文件** — `data/` 目录下的 JSON 文件由对应角色负责更新，更新后修改 `last_updated` 字段

## 搜索规范

1. **真实数据优先** — 使用 `web_search` 获取真实赛事、优惠和场馆数据，不得编造信息
2. **来源标注** — 所有搜索结果必须标注信息来源（网站名称或链接）
3. **时效标记** — 标注搜索时间，过期信息需重新搜索验证

## 质量标准

1. **内容审查** — 督导官负责审查所有内容后方可视为"发布就绪"
2. **场馆信息** — 地址、容量、设施等场馆信息必须经过验证，不得凭记忆填写
3. **优惠信息** — 所有优惠推荐必须包含有效期，过期优惠及时标记或移除
4. **赛程数据** — 赛程变动需及时更新 `data/schedule.json`，标注 status 变化

## 任务规范

1. **持续监控** — 亦城创建周期性任务，保持赛事动态和优惠信息的持续更新
2. **任务管理** — 通过 JaMOSS API 创建、分配和跟踪任务，不得跳过任务系统直接行动
3. **不跨界修改** — 不得直接修改其他成员的内容产出，通过 JaMOSS 任务沟通修改需求
4. **日志记录** — 每次重要操作后写入活动日志，方便回溯和协作

## 协作规范

1. 遇到问题先查已有数据和日志，再尝试搜索解决，最后才通过任务求助
2. 返工时必须针对审查意见逐项修复，不要遗漏
3. 每次自省笔记不要重复已有内容
4. 赛事日优先保障电竞官和应援官的内容产出，非赛事日侧重生活官和巡城官
5. 督导官审查队列积压时，亦城应优先安排审查任务
6. 巡城官发现异常后由亦城统一协调处理，巡城官不直接干预执行
