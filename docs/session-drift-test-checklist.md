# Session 状态漂移修复 - 测试清单

## 测试场景

### 1. 基础切换测试 ✅

**步骤**:
1. 创建 Session A，发送消息 "测试消息 A1"
2. 等待 AI 回复完成
3. 创建 Session B，发送消息 "测试消息 B1"
4. 在 Session B 流式渲染期间，立即切换回 Session A
5. 检查 Session A 是否显示完整的对话历史（包括 AI 回复）

**预期结果**:
- Session A 显示完整历史，不丢失消息
- 不出现消息重复或顺序错乱

### 2. 快速切换测试 ✅

**步骤**:
1. 创建 3 个 session (A, B, C)
2. 在每个 session 中发送一条消息
3. 快速切换：A → B → C → A → B → C
4. 检查每个 session 的消息是否正确

**预期结果**:
- 每个 session 的消息独立，不混淆
- 切换延迟 <500ms

### 3. 流式渲染期间切换 ✅

**步骤**:
1. Session A 发送长消息（触发长时间流式渲染）
2. 流式渲染进行到一半时，切换到 Session B
3. 在 Session B 发送消息
4. 切回 Session A，检查流式渲染是否正常完成

**预期结果**:
- Session A 的流式渲染不受影响（或正确中止）
- Session B 的消息正确保存
- 切回 Session A 时显示完整历史

### 4. 重启 App 后恢复 ✅

**步骤**:
1. 创建 Session A，发送多条消息
2. 关闭 App（不等待 persist 完成）
3. 重新打开 App
4. 检查 Session A 的消息是否完整

**预期结果**:
- 所有已 persist 的消息都能恢复
- 最后几条消息可能丢失（如果 persist 未完成），但不会出现部分消息或错乱

### 5. 网络断开时的行为 ✅

**步骤**:
1. 断开网络
2. 发送消息（persist 会失败）
3. 切换到另一个 session
4. 恢复网络
5. 切回原 session

**预期结果**:
- 网络断开时，persist 失败会有错误提示
- 恢复网络后，重试逻辑自动补救
- 消息最终正确保存到 DB

### 6. 定期刷新机制 ✅

**步骤**:
1. 在设备 A 打开 Session X
2. 在设备 B 打开同一个 Session X，发送消息
3. 在设备 A 等待 5-10 秒（不切换 session）
4. 检查设备 A 是否自动显示设备 B 的新消息

**预期结果**:
- 5 秒内，设备 A 自动刷新并显示设备 B 的消息
- 不需要手动切换或刷新

### 7. 匿名会话（本地模式）✅

**步骤**:
1. 创建匿名会话（anonymous: true）
2. 发送消息
3. 切换到其他 session
4. 切回匿名会话

**预期结果**:
- 匿名会话不调用 DB persist
- 消息保存在本地内存
- 切换后消息仍然存在（在 sessions 列表中）

### 8. 长对话压缩后切换 ✅

**步骤**:
1. 在 Session A 进行长对话（触发 compaction）
2. 压缩完成后，切换到 Session B
3. 切回 Session A

**预期结果**:
- Session A 显示压缩后的历史（摘要 + 近期消息）
- 不出现重复或丢失

### 9. 并发写入冲突 ⚠️

**步骤**:
1. 在设备 A 和设备 B 同时打开 Session X
2. 同时发送消息（触发并发 persist）
3. 检查 DB 中的消息顺序

**预期结果**:
- 两条消息都正确保存
- 顺序可能不确定（取决于网络延迟）
- 不出现消息覆盖或丢失

**已知问题**: 当前没有乐观锁（version 字段），可能出现后写覆盖前写（last-write-wins）

### 10. 性能测试 ✅

**步骤**:
1. 创建 10 个 session，每个包含 50 条消息
2. 快速切换这 10 个 session
3. 测量切换延迟

**预期结果**:
- 平均切换延迟 <500ms
- 不出现 UI 卡顿或冻结

## 已知限制

1. **并发写入冲突**: 多设备同时编辑同一 session 时，可能出现消息覆盖（last-write-wins）
   - **缓解**: 添加乐观锁（version 字段）或 CRDT
   
2. **定期刷新延迟**: 5 秒刷新间隔，多设备同步有最多 5 秒延迟
   - **缓解**: 使用 WebSocket 推送实时更新

3. **网络断开时消息丢失**: 如果 persist 重试 3 次都失败，消息会丢失
   - **缓解**: 添加本地队列，重连后自动同步
